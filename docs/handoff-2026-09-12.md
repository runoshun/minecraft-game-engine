# Handoff: Vanilla-first Portable DSL / Fabric retirement work

Date: 2026-09-12

## 1. Executive summary

The project direction has changed from "Fabric runtime is the primary game runtime" to **"TypeScript `portableDsl` -> versioned Portable IR -> generated vanilla datapack is the primary deployment path"**.

Fabric is intentionally still present as an optional development/compatibility backend. The engineering goal is to remove it once the retirement gates in ADR 0013 are satisfied.

The latest in-progress work is **Portable IR / DSL v5**. It adds the missing primitives needed to express a real brick-breaker and starts the pinball path:

- compile-time `game.repeat(...)` for bounded static collections;
- conditional `game.block(..., { when })` / `game.text(..., { when })` visibility;
- `game.circle(...)` and deterministic circle/circle `game.whenColliding(...)`;
- vanilla-first documentation and retirement criteria.

A full 5 x 8 / 40-brick Breakout is authored only with `portableDsl`, compiles to a standalone datapack, and has now passed the full mod-free `second` E2E gate. Real-client A/D + Space input, fixed camera, brick destruction/visibility, score, lives, HUD, reset behavior, particles/sound command execution, cleanup, and proof recording were exercised on Minecraft 26.1 with `loader=vanilla`, `mods=[]`, and `installed_jars=[]`. The E2E pass also found and fixed text-display component double encoding.

Fabric is still **not** removable: ADR 0013 gate 1 is now green, but the pinball gate and gates 3-5 remain open.

## 5. v5 implementation status

### 5.1 Static collections

`game.repeat(count, builder)` is implemented in the DSL frontend.

It is a **build-time expansion helper**, not a runtime loop in Portable IR. The builder callback executes while constructing the IR and returns a bounded static collection that can be iterated while the `tick(...)` declaration is being built.

This lets a source file express a brick grid without adding dynamic collections to the datapack runtime.

### 5.2 Conditional presentation visibility

`game.block` and `game.text` accept `when: PortableDslCondition` in v5.

Vanilla backend behavior:

- Display entities remain owned/alive;
- visible state uses the declared `transformation.scale`;
- hidden state sets scale to `[0f,0f,0f]`.

Fabric compatibility behavior:

- the adapter spawns/removes the corresponding render node based on the same condition.

This is what allows an individual brick to disappear when its `alive` state becomes 0.

### 5.3 Circle collision

Implemented:

```ts
const ball = game.circle("ball", { x, y, radius: 0.25 });
const bumper = game.circle("bumper", { x: 1, y: 2, radius: 0.5 });

game.whenColliding(ball, bumper, () => {
  // state actions
});
```

IR operation: `if_circle`.

Both backends quantize fixed-point coordinate deltas to roughly 0.01-block units before squaring, to stay inside Minecraft scoreboard signed 32-bit arithmetic. This is deterministic arcade collision, not a general physics solver.

Still missing:

- box/circle mixed collision;
- segment/capsule collision;
- rotating segment/flipper semantics;
- swept collision;
- general collision response/normal calculation.

## 9. Fabric retirement gates

Do not delete the mod simply because the simple Breakout path works.

ADR 0013 defines these gates:

1. Full reference Breakout passes E2E from generated vanilla output, including brick destruction/reset, score, lives, input, camera, HUD, sound and effects.
2. A representative pinball prototype passes from generated vanilla output, including bumper/flipper/trigger primitives.
3. Required game-facing UI/input features have vanilla portable mappings, or are explicitly declared out of scope.
4. Generated ownership/reload/cleanup is reliable enough that Fabric is not needed as a lifecycle safety net.
5. Normal development no longer depends on arbitrary runtime TypeScript callbacks or Fabric-only host capabilities.

Current status: gate 1 is **E2E-passed on the mod-free `second` server**. Gates 2-5 remain open.

## 11. Known limitations / traps

- Portable DSL is deliberately restricted. It is not a general TypeScript-to-mcfunction compiler.
- `repeat` and `for ... of` over its returned static array run while building the IR, not as datapack runtime loops.
- State/input remain fixed-point scalar values; there are no runtime arrays/maps/dynamic entities yet.
- Circle collision is quantized and circle/circle only.
- Conditional visibility zero-scales Displays instead of despawning them.
- Camera currently supports one controller.
- Camera cleanup restores Adventure rather than preserving arbitrary previous gamemode.
- Vanilla target is Minecraft 26.1; generated commands/predicates are version-specific.
- Large static games can produce many scoreboard commands and branch functions. Watch tick cost as the DSL grows.
- Fabric-only generic menus/sidebar/render actors/world mutation still exist and are not automatically portable.
- Signed mc-mcp capture URLs expire; do not use old video URLs as durable project documentation.
- Source/build/git work must use `devcontainer-mcp` (`minecraft-game-engine-work`); Minecraft/datapack/mod deployment and E2E must use `mc-mcp`.
